# Existing optional report email alerts

> This legacy integration is separate from new student academic subscriptions ([NOTIFICATIONS.md](NOTIFICATIONS.md)). These are operator instructions only: no Google account/project, real mail recipient, or external deployment was changed or tested in this upgrade. Confirm the target deployment belongs to **Ahmedamir21/Plan** and obtain separate authorization before configuration or a real test email.

The admin inbox works without email. These steps **optionally** send a short alert from an admin's Google account to two admin addresses whenever a student report arrives. You do **not** provide your Gmail password to Planora or put either admin's email in the public repository. The report itself stays in the private admin panel. Setup needs access to one admin's Google account and to the verified Plan repository's deployment environment settings. Google quotas and terms may change, so lifetime free delivery is not guaranteed.

1. Sign in to the Google account that should **send** the alerts. Open [script.google.com](https://script.google.com/), select **New project**, and name it **Planora report alerts**.
2. Open `scripts/planora-report-mailer.gs` from this repository. Replace the template content in Apps Script's `Code.gs` with that file, then click **Save**.
3. In the Apps Script editor, open **Project Settings** (gear) → **Script properties** → **Add script property**. Add `AHMED_EMAIL` (Ahmed's receiving address) and `YOUSSEF_EMAIL` (Youssef's receiving address). Add `PLANORA_MAIL_SECRET`: a private, random string of at least 32 characters. You can generate it locally with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Keep its value private. This is a webhook secret; **it is not a Gmail or admin login password**.
4. In Apps Script select **Deploy → New deployment → Web app**. Set **Execute as: Me** and **Who has access: Anyone**, then deploy. Google may ask you to authorize the script to send email **from your own account**. Copy the Web app URL ending in `/exec`. Its endpoint is protected by the private secret from step 3; never share the secret or put it in GitHub. If Google does not offer this setting for your account, stop here; the admin inbox still works.
5. In Vercel, open the verified project connected to **Ahmedamir21/Plan** → **Settings → Environment Variables**. In **Production**, set `PLANORA_REPORT_MAIL_WEBHOOK_URL` to the URL from step 4 and `PLANORA_REPORT_MAIL_WEBHOOK_SECRET` to the **same** secret from step 3. Save both privately. Make one deployment after the other requested changes are complete (no need to redeploy for each variable).
6. After deployment, submit a single test report on Planora. Confirm it appears in the admin inbox and check its **Email alert** status. Confirm both recipient inboxes received the alert. If the alert says `failed`, the report is still safe in the admin inbox; check the Apps Script **Executions** tab and both secret values. If it says `not configured`, the Vercel values are missing or the production deployment has not loaded them.

The email contains a course summary and a link to `/admin.html`, not the student's message. The Google Apps Script source and public GitHub repository contain **no real email addresses or secrets**. The receiver can update the two addresses in Apps Script Script properties without editing Planora code. To stop alerts, remove the webhook URL from Vercel; this does not delete reports.

## Optional private admin sign-in alerts

After replacing the deployed Apps Script with the current `scripts/planora-report-mailer.gs` and deploying its updated web app, add `PLANORA_SECURITY_MAIL_ENABLED=true` to Vercel Production. A successful admin sign-in sends an alert to the same two private email addresses. The first rate-limited request from an IP within a 15-minute window sends another alert. Failed and blocked attempts are recorded in the private admin security panel, even when email is disabled. Mail failures do not block sign-in or erase events. Do not enable the flag until the updated Apps Script is deployed: an old receiver does not understand security events. Security mail includes the IP, approximate browser and OS, time, and username entered; never passwords, cookies, or tokens. Failed username entries are unverified visitor input. To stop these emails alone, remove the flag or set it to `false`.
